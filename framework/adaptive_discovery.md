# 自适应探索引擎｜Adaptive Discovery

> v0.4 · 提问路由的方法规范，不是心理测量量表或已经自动运行的服务。

## 核心目标

让没有研究经验、没有心理学知识、不会提问的人，也能通过**自然交谈**逐渐建立自己的分析架构。深度可以相当，内容不需要相同。

**框架可以组织问题，但不得把具体的人强行写成固定的 12 栏/20 栏，也不能为了覆盖率诱导披露创伤、健康、性或第三方隐私。**

## 0. 首问：不是“你是哪种人格”

邀请用户从以下入口中**任意选择一个**：最近在意的事、喜欢的人或作品、一个重复出现的行为、一次选择、一个疑问、一个普通的快乐。用户无需预先选定人格维度。

默认首问：“最近有什么事情让你特别在意，或者让你觉得自己好像和以前不一样？” 如果用户只是想试用，可以改为：“你愿意从最近一件小事说起吗？”

不愿回答时：换更轻的入口或暂停；不追问原因。

## 1. 下一问路由：按信息增益而不是固定题序

每轮只选择**一个**最有助于理解且不侵犯边界的问题。先判断当前材料最缺什么：

| 缺口 | 最合适的下一问（任选其一） |
| --- | --- |
| 没有具体情景 | “你能想到最近的一次具体例子吗？” |
| 只有行为，没有本人意义 | “当时这件事对你意味着什么？” |
| 已有解释但不确定 | “有没有一次相反的经历？” |
| 多人关系不清楚 | “谁做了什么？你知道的是对方原话还是你的猜测？” |
| 似乎有长期变化 | “以前碰到类似的事，你会怎么做？” |
| 把价值与责任混在一起 | “你觉得它很重要，是否也意味着你必须亲自去做？” |
| 有宏大意义但缺普通生活 | “离开目标和责任，什么活动本身让你开心？” |
| 遇到不愿说的话题 | “我们可以跳过；想聊更轻松的，还是先到这里？” |
| 不知道该怎么归类 | “你自己的词是什么？不需要使用心理学名称。” |
| 目前没有信息缺口 | 停止提问，自然回应；不把每次聊天变成研究访谈 |

每个问题都应回答：**为什么现在问这个？什么回答会区分两种解释？** 无法回答时不要机械发问。

## 2. 个体发现路线，不设统一人格问卷

可在适合的时机使用以下探索领域作**提示地图**，默认不依次盘问：

| 领域 | 人会自然产生的问题 | 可选探索问句 |
| --- | --- | --- |
| 感受与状态 | 今天什么让我有力量/疲倦 | “哪些时候你明显更自在？” |
| 学习与思考 | 我怎样发现问题、改变观点 | “有没有一次你后来承认自己想错了？” |
| 动机与价值 | 想要、需要、珍视、应该 | “有什么你珍视，却不打算拥有或实现？” |
| 决策与行动 | 能做、要做、选择不做 | “你最近放下过一个本来做得到的事情吗？” |
| 关系与边界 | 友情、家庭、爱、合作 | “怎样的互动让你觉得被尊重？” |
| 身份与角色 | 我是什么人、我扮演什么角色 | “有没有一个别人习惯用来描述你、你却不完全认同的称呼？” |
| 时间与成长 | 过去我与现在我 | “哪一种改变，你是后来才发现的？” |
| 工作与能力 | 做得好与真正喜欢 | “你擅长的事里有没有你不想一直做的？” |
| 文化与审美 | 阅读、音乐、地方、人物 | “有没有一个作品改变了你看世界的方式？” |
| 创造与好奇 | 新想法、作品、探索 | “什么问题你会不计回报地反复琢磨？” |
| 日常与身体 | 作息、休息、环境 | “普通的一天里什么瞬间值得你留住？” |
| 不足、矛盾与未知 | 局限、冲突、例外 | “有没有一个看起来矛盾的你，其实都是真的？” |

以上是可选“发现问题”，**不是每人都要回答的 12 道题**。详见 [生活专题](personal_domains.md)。健康与亲密领域默认更加克制。

## 3. 深挖、广度与停止

- **深度**：有真实兴趣和足够材料时围绕同一主题追问事实 → 体验 → 解释 → 相反例子 → 时间变化 → 新问题；不固定先后。
- **广度**：只有用户希望完整盘点时，查看哪些主题是“材料丰富 / 有线索 / 未知 / 用户不想记录”；未知不意味着人格缺失。
- **Information gain**：优先问能区分至少两种竞争解释的问题，而不是为了好看的理论叙述找支持证据。
- **Long-tail**：可偶尔邀请探索被常规问题忽视的普通生活、兴趣转折、失败修复、关系中的差异、未选择的路径、制度与环境影响。但不故意搜寻创伤或稀有秘密。
- **停止**：用户表示停下、疲惫或不想被分析时立即停止；对话可以只聊天而不形成模型。

## 4. 六种对话模式（可由本人选择）

`chat` 普通聊天；`explore` 细谈一件事；`contrast` 搜索反例；`map` 开放式领域盘点；`review` 对照旧结论；`report` 汇总现有证据。

自动路由最多是提议；用户可以随时切换、跳过、要求短回复。**不要让用户必须了解模式名称才能使用。**

## 5. 一轮会话的最低质量检查

1. 本次问题源于用户当前兴趣还是系统想填空？
2. 我是否先正确复述了她/他的原话，而不是直接提供人格解释？
3. 下一问是否真的有意义？是否可以不问？
4. 这是谁的自述或行为？第三方有无独立视角？
5. 若形成新假设，反例与适用情境是什么？
6. 当事人能否轻易说“不对”“跳过”“我还不知道”？
7. 重要信息是否可以在**不泄露私人资料**的前提下回到其自有存储？

## 6. 何时进入 Output

- 五分钟体验后：输出一个简短、临时、有证据的观察即可，不强称“全人格”。
- 一个主题探讨充分后：输出专题深描，保留未解问题。
- 用户要求全面/阶段报告时：使用 [完整报告方法](output_reports.md) 和 [完整报告提示词](../prompts/full-report.md)，只根据真正可见资料生成，缺失要标注。
- 更新既有报告时：只更新相关章节并记录变化；不能凭最新一次聊天覆盖旧事实。

> **一个好问题能帮助人自己展开，而不是预先替他决定自己是什么样的人。**
