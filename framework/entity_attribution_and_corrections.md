# Entity & Attribution Gate｜先认清是谁，再理解说了什么

> 通用错误防线。**不同人、同名昵称、引用与多平台别名不能靠语义相近自动合并。** 第三方的感受/意图不能由 AI 替其认证。

## 每次引入多人材料时的四个问题

1. 原文本**谁发送**？是本人、第三方、转述者、引用块、AI 回复，还是无法判断？
2. 不同截图/文件里的标识是否真的指向同一人？有**明确可核实的映射**，还是只是名字像、谈话风格像？
3. 这句话描述的是**谁的经历/感受**？发言人也可能讲他人事情；“我”要随语境重新定位。
4. 事件发生时间、聊天记录时间、今天解释时间是否不同？

## 最小实体登记（仅私人仓库）

优先使用本地非身份化 ID：P-SELF、P-01、P-02。对应关系只在私人必要范围维护，不上传公共代码库。参见 [实体登记模板](../templates/ENTITY_REGISTER_TEMPLATE.md)。

| 字段 | 做法 |
| --- | --- |
| entity_id | 不随更名重排 |
| 标签/别名 | 有来源才关联；未确认映射保持分离 |
| speaker_of | 来源记录位置，引用块另标发言者 |
| subject_of | “被讨论的是谁”，不一定等于 speaker |
| match_status | VERIFIED / UNVERIFIED / CONFLICT |
| privacy | PRIVATE / LOCAL_ONLY / DECLINED |
| check | 何种原始证据足以确认或推翻关联 |

**别名规则：**没有明确关联证据，两个人永远不能因为同名、同题材或共同好友被合并。人物关系推断也不得递归推出未知身份。

## 错误发生后的污染追溯

当使用者说“你把 A 和 B 搞混了 / 这句话是我说的”：

1. **先承认并定位错误。** 不用含糊的“可能误会”淡化明确纠正。
2. 暂时冻结受该归属支持的所有结论、评分、关系推断和输出；不能继续引用。
3. 逐个检查被污染的 evidence、claim、报告段落、问题库来源及分享稿，列出依赖项。
4. 用正确的说话者和来源修订原始记录的**标注**，保留错误更正日志；不把先前 AI 猜测当原始事实。
5. 受影响结论执行 RETRACTED 或 REVISED；无新增证据时不重建同一个判断。
6. 用户确认必要事实后，才能基于真实资料重新推断；相关更新只能写在有授权的私人存储。
7. 告知用户哪些文件改好了、哪些没有权限改或尚未找到；**一处改正不等于整个系统自动正确**。

## 与独立模型区分

- **ENTITY_ERROR**：人物归属错误，优先于人格/关系解释；要撤回依赖它的解释。
- **INTERPRETATION_ERROR**：来源正确，但候选机制缺乏反例；降低权重或重写。
- **TEMPORAL_CHANGE**：过去描述真实、现在不同；不是必须“撤回过去”。
- **SOURCE_MISSING**：无权读取旧记录；不是旧记录不存在。
- **USER_DECLINED**：本人拒绝保存或讨论，不等于该主题没有真实经历。

## 完全虚构的纠错例子

在一个虚构的社区花园聊天里，甲转发了乙写的“我更喜欢安静的地方”，AI 却当成甲的自述。甲说：“那句是乙说的。”正确操作是将**甲偏好安静**的相关结论撤回，并标注乙的引用来源；没有独立材料时，不再猜测甲喜不喜欢安静。

这只是方法演示，与任何真实用户没有对应关系。

> 好的长期记忆不仅记住发现，也能精准撤回错误传播的整条解释链。
