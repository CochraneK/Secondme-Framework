# Question Atlas｜保留一个人真正问过什么

> 一个问题可以比一个标签更能展现使用者的兴趣与选择，但**提问不等于赞成、亲身经历、当前目标或心理症状**。

## 两种不能混算的问题

- **Historical Atlas：人 → AI / 世界**。只保存明确可见的历史提问、追问或行动请求。必要时把反复探索的主题单独做 NORMALIZED 摘要，但不能冒充逐字原话。
- **Discover/Understand：AI → 人 / AI 核查自己**。AI 可以自愿邀请用户分享经验、寻找反例；Understand 问题应检查 AI 是否过拟合、忽略普通生活、归错人物。它们属于**探索题库**，不计入本人历史问句数。

## 历史问题条目最小格式

| 字段 | 要求 |
| --- | --- |
| Q-ID | 稳定编号，不重排；不要求与其他人的编号一致 |
| quote_or_paraphrase | REAL_VERBATIM / VERIFIED_EXCERPT / NORMALIZED / ASSISTANT_PROPOSED |
| text | 原话在授权可见时保留；NORMALIZED 不加用户引号 |
| source_pointer | 真实可访问的消息、材料或本人提供的摘要 |
| time_scope | 可核实则记，未知则 UNKNOWN |
| themes | 按个人主题命名，可跨域而不重复计条数 |
| privacy | 禁止在公共模板存放填好的个人问句 |
| status | 历史、正在探索、已放弃与任务均不得混成 Todo |

**禁止假精确**：不能声称抓取全账号历史、编造消息 ID、把 AI 建议改写成用户问过的问题、把同一个问题的不同摘要重复计入“真实问句数”。

## 从一份问题库获得什么？

1. 哪些主题出现得多？这只是当前资料分布，不是兴趣的全貌。
2. 怎样追问：要求来源、反例、实际运行、其他方法，或跨领域延伸？
3. 随时间哪些问题消失、回来或被实际作品回答？
4. 哪些重要的普通生活主题目前没有记录？空白也可能是抽样偏差。
5. 对读者公开时，只导出本人授权且经过隐私审阅的条目；私人问句目录不等于公开传记。

## 对接已有双向系统，而非重做固定问卷

Discover Me / Understand Me 的通用问题方法在独立审核中（见仓库 PR #1，未合并前不能把它说成 main 已发布内容）。即使未来合并，也应把“AI 推荐了一个新问题”与“用户实际提出过一个问题”分开保存。54、108、379 等不是所有用户的规定数量、目标分数或效果标准。
