# SecondMe 双向问题系统 v0.2 · Discover Me × Understand Me

> **状态**：可复用的实验性访谈与自我反思框架，**非标准化量表、非临床筛查或已验证的最优题序**。公开文件只包含抽象方法和通用题目；不含任何真实个人的私有聊天、人物画像或临床数据。  
> **两个入口**：[AI → 用户：Discover Me](../questions/discover-me.md) · [用户 → AI：Understand Me](../questions/understand-me.md) · [直接复制的对话提示词](../prompts/two-way-questions.md)  
> **已有基础**：[Human Ontology](human_ontology.md) · [个人生活专题](personal_domains.md) · [证据协议](evidence_protocol.md) · [自适应探索](adaptive_discovery.md) · [引导式对话](../prompts/guided-exploration.md) · [寻找下一问](../prompts/next-questions.md)。

## 1. 目的：两种方向、两种不同的任务

| 方向 | 想解决的问题 | 首要产物 | 不应混淆 |
| --- | --- | --- | --- |
| **Discover Me（AI → 人）** | 在本人自愿、低负担前提下，怎样用尽量少的问题建立一个有用的初始模型？ | 真实事件、自述偏好、当前处境、待验证解释、缺口与边界 | 好的聊天体验 ≠ 人格测量效度；一个人的自述 ≠ 外部事实完全核实 |
| **Understand Me（人 → AI）** | 已有资料后，使用者怎样借 AI 发现优势、局限、矛盾、他人视角、变化与盲区？ | 有证据来源的假设、竞争解释、反证、修订问题 | AI 说得动人、详细 ≠ 更正确；AI 的描述 ≠ 本人已经认可 |

第二方向不能沦为“AI 夸赞用户”，第一方向不能沦为“尽快给人贴人格标签”。它们共享一套**可反驳的证据台账**，通过自然对话交替使用。个人内容属于使用者自己的私有空间，**不进入公开 Framework**。

## 2. 设计来源与边界

本框架**由 SecondMe 已有的 12 维导航、20 类生活资料、自然对话、证据/时间/反证规则、深层问题发现思路重新组织**。题目措辞、先后次序、默认六题及选题启发式是**新设计假设**，不是从历史个人案例里统计出的最优解。

可借鉴的外部方法：
- **McAdams Life Story Interview**：通过人生章节、关键场景、转折和意义叙述理解生命故事；本框架将其简化为具体经历与跨时间追问，**不声称等同原工具**。来源： https://www.northwestern.edu/magazine/winter2005/feature/redemption/sidebar1.html
- **Vazire SOKA（自我—他人知识不对称）**：某些个人特征可由当事人/他人各自观察到不同部分；启发多视角和不确定性处理，**不推出任何一方总是更正确**。来源：https://pubmed.ncbi.nlm.nih.gov/20085401/
- **动机式访谈 OARS**：开放提问、反映性倾听、概要整理、尊重自主选择；作为沟通技巧参考，**此处不是治疗实施**。来源：https://nida.nih.gov/sites/default/files/oarsessentialcommunicationtechniques.pdf

## 3. 两层架构：上层维度地图，下层自适应问题

**维度层**：依托现有 Human Ontology 的 12 个可交叉观察视角（身体/状态、认知、人格、情绪、价值、社会关系、文化环境、能力、创造、经历、身份、时间）。不必每题对应唯一维度，不以“12 维填满”作为目标。20 类生活专题用来找到用户自身重要的具体内容，不要求全部覆盖。

**问题层**：先有一个轻松的现实事件，动态选 1 个最有信息价值、本人愿回答的问题。Discover Me = **6 个首轮核心 + 18 个通用补充 + 24 个自选专题（共 48）**；Understand Me = **6 个核心镜像 + 18 个深化 + 24 个自选专题（共 48）**。六题是起步路线而不是必须按顺序问完；扩充后的 96 个候选绝不是 96 问顺序问卷。用户已提供某主题内容就不重复问。对话不用显示题号，除非用户要求。

### 访谈状态机

```text
用户目的与同意
  ├─ 仅聊聊：自然回应，不执行评分
  ├─ 初次探索：Discover Me（提问 → 复述 → 确认/更正）
  └─ 已有材料：Understand Me（检索 → 带证据回答 → 接受质疑）
                         ↑                    ↓
            真实新事件 / 反例 ← 具体新问题 / 微小观察
```

**每轮限一个主问题**。AI 可在提问前做简短复述，但复述不能偷偷变成未经认可的人格结论；用户可说“跳过”“不要分析”“不要保存”“先停”。

### 提问路线：默认优先选择哪类材料？

1. **当下真实事件**：发生了什么，尤其是具体行动、选择和互动。
2. **本人意义**：那件事为什么在意？感受和价值是什么？
3. **情境与条件**：什么环境/资源/角色改变表现？
4. **竞争解释**：有没有同样合理但不同的解释？最缺哪条证据？
5. **反例与变化**：何时并非如此，过去和现在是否不同？
6. **其他人看到的部分**：他人实际说过什么，而不是推测其内心。
7. **日常快乐与普通生活**：防止只从成就、痛苦和冲突认识一个人。
8. **边界与修正权**：什么不愿谈，AI 的哪条理解应当撤回？

只抽取当下最相关的路线，**不强制每轮八步齐做**。

## 3.5 题库扩充后的三种入口：事件、专题、提问历史

问题来源与来源类型不能混为一谈。**以下三种入口只决定怎样找到问题，不会自动提升对人的结论等级。**

| 入口 | 触发 | 可以调用 | 预期证据与边界 |
| --- | --- | --- | --- |
| **真实事件优先** | 用户分享了一件近事、一个选择、一个互动 | D01–D24 / U01–U24 | 先确定行动和情境，再考虑人格；默认选择 |
| **本人在意的专题** | 用户自愿谈关系、审美、创作、梦境、家庭、领导或价值取舍 | D25–D32、D39–D48 / U25–U32、U41–U48 | 针对自己的体验，不能将第三方意图、象征、兴趣直接定型 |
| **提问历史入口** | 用户明确要求“根据我问过的问题认识我”，并授予可访问的记录 | D33–D38 / U33–U40 | 分别记录真实原话、摘要重写、AI 生成候选；按实际可访问分母计数，禁止把问句推成信念 |

### 一次“最有价值的下一问”路由

1. **先判断用户要什么**：是随意聊天、要一个现实建议、初次访谈，还是希望系统审查人物模型？普通问题先直接回答，不把所有交流变成人格采集。
2. **可见性闸门**：能否看到此前资料？若不能，说明局限；不得虚构完整问题历史或声称跨会话自动检索。
3. **候选限制**：按用户当前话题选 1–3 个可能有帮助的问题方向；将用户明确拒绝、过于敏感、已有充分材料的题目排除。
4. **区分性评估**：如果两种解释都可能成立，优先问能把它们区分开的一个具体生活例子；如果只是缺原文或缺事实，先检索或请求授权。
5. **对话最小化**：每轮**最多一个**主问题；足够时直接回答或结束，不用凑满题量。
6. **更新与退出**：用来源与反例写候选结论，提示用户能拒绝、纠错、停止与选择不保存；不因同意聊天而自动授权永久归档。

### 参考性的双向配对（非强制顺序）

| 用户正在谈的内容 | AI 可以补问 | 用户可能反问 AI |
| --- | --- | --- |
| 对一个人感到亲近，但关系难定义 | D25、D26、D28 | U25、U26、U27 |
| 给人帮助很多，却不确定是否被真正喜欢 | D27、D30、D31 | U28、U31 |
| 总想寻找新的知识问题、跨领域联想 | D33、D35、D36 | U33、U35、U36、U37 |
| 喜欢历史人物、虚构角色、音乐或古建筑 | D39、D40、D41 | U41、U42 |
| 分享梦与现实的巧合 | D44（仅本人主动） | U44（保留未应验对照） |
| 对自身类型标签或人格画像感兴趣 | D48（本人自愿） | U47、U48 |
| 有能力帮助别人，却不知是否应该承担 | D45、D46、D47 | U45、U46 |

**不会为了提高既有历史问题库的“覆盖率”而强行扩张采访**：长期记录包含代码、研究、技术方案和执行命令，它们首先是特定领域请求；只有当用户明确希望分析长期提问风格时，才以可见、可复核的提问素材进入个人模型。即使用户的提问表现出跨学科兴趣，也不能直接推导其智力、道德或临床状态。

## 4. 如何选择“下一问”：可解释、可退出、暂未标定的规则

先列当前模型的 1–3 个高价值未知、竞争解释或已显现的情境约束，再对候选题进行相对比较：

| 评价维度 | 更应被选择的题目 | 应降优先级的题目 |
| --- | --- | --- |
| **新信息 / 边际增益** | 回答后能区分两个实际影响解释的候选 | 重复已有事实、只是换个措辞 |
| **行为与情境锚点** | 可以说出一次真实发生的事件 | 只能得到抽象的“我一向如何” |
| **覆盖缺口** | 补当前严重遗漏、又与用户目标相关的生活面 | 为填满目录而强制挖掘不相关专题 |
| **反证能力** | 允许发现 AI 先前判断不成立 | 问法暗示 AI 希望的答案 |
| **回答负担与安全** | 低成本、易跳过、尊重当前边界 | 强逼秘密、创伤、健康、性、他人隐私 |
| **用户意愿** | 用户说希望谈或主动展开 | 用户回避、拒绝或明确不感兴趣 |

不以未校准的数值宣称“信息增益提升 X%”；暂采用**先安全、后相关、再最大化区分度**的定性选择法。真正评估需要前瞻性数据。问了六题仍不知道时，应承认不知道，不为“完成画像”补故事。

## 5. 回答与蒸馏：每个结论至少保留什么

建议统一输出一张可反驳的「人物认识卡」，仅包含已有材料支持的内容：

| 字段 | 说明 |
| --- | --- |
| CLAIM / 判断 | 只说到已有证据能支持的精度，避免永久人格标签 |
| SOURCE / 原始来源 | 引用用户哪次自述、本人行为、他人明确发言；若无则写 unknown |
| TIME / 时间 | 事件发生、记录、后来反思的时间尽量分开 |
| TYPE / 来源类型 | SELF_REPORTED / EVENT / OBSERVED / EXTERNAL / INFERRED / UNKNOWN |
| CONTEXT / 条件 | 在何种场景成立、是否有资源/身体状态约束 |
| ALTERNATIVE / 竞争解释 | 至少一个合理的替代理由；不强迫两个解释等概率 |
| COUNTEREVIDENCE / 反证 | 已知反例或下一次最值得观察的行为 |
| SUPPORT / 支持度 | insufficient / low / medium / high，定性判断，不等于统计概率 |
| STATUS / 状态 | provisional / active / weakened / superseded / retired |
| USER CORRECTION / 本人修订 | 明确记录“这不准确”“并非这样”“不愿保存”并同步降权 |

> **特别规则**：收藏了一句话 ≠ 认同；听到老师的方法 ≠ 掌握；欣赏某人物 ≠ 与他相似；问及疾病 ≠ 患病；梦境/虚构 ≠ 现实意图；好奇一种机会 ≠ 已作承诺。

### 用户问 AI 的最低回答标准

1. 先给结论及其适用范围（不敷衍，也不神秘化）。
2. 用可见事实举 1–3 个支持例子，讲清来源和时间；若缺材料则承认。
3. 至少提供一个竞争解释或限制条件；重要判断给可检验反例。
4. 给用户纠正和跳过权；不要把提问自动变 Todo。
5. **能够回答“你是不是在安慰我？”和“你从哪里知道？”**，并及时降低错误结论权重。

## 6. 运行模式

| 模式 | 推荐使用 | 提问方式与产物 |
| --- | --- | --- |
| **Quick / 轻量** | 初识、时间有限、低负担 | 从 Discover 核心六题中选 2–3 题；仅输出当前处境、本人重视之事与明确未知 |
| **Core / 标准** | 用户主动想初步认识自己 | 从 Discover 核心六题选取必要问题，最多再选 1–3 个真正缺失的追问；输出来源注明的认识卡 |
| **Longitudinal / 纵向** | 有不同阶段资料、用户允许继续 | 多次会话对比重要行为、反例和改变；必要时按需调用新增专题题与提问历史模块；不以某固定完成率结束 |
| **Mirror / 镜像** | 用户已拥有材料，主动向 AI 提问 | 从 Understand Me 的 48 道候选中选择用户指定的一题，检索与比较后回答，不再把用户当从零采访的对象 |

以上问数是**产品原型设定**，不是研究确认的最优个数或时长保证。

## 7. 停止条件和敏感性保护

- 用户要求停止、跳过、删除/不记录，或只想随意聊天时即停止访谈模式。
- 用户已经表达当前足够满意，或新增问题只能得到重复、猜测、过度私密材料时停止。
- 任何人都无须透露家庭创伤、医疗史、财务、性与亲密关系细节才能获得分析；不得要求第三方私人原始聊天/可识别身份。
- AI 不是临床诊断者；若对话出现危机/安全问题，优先处理安全，不继续人格蒸馏。
- 未经过用户明确授权，不将私人访谈、人物卡或模型输出写入公共 Git、发送给外部模型服务或自动训练。
- 优先让人用自己的话表达；不要求每个人都擅长写长文本，用户可只说一个例子或选择“我不知道”。

## 8. 验证计划（仍待真实数据）

**不能用同一位长期熟悉的使用者的完整人物报告设计题目，又拿该报告作为独立测试结果。** 需区分题目构思资料和留出评估集，最好多位自愿参与者的跨背景数据，严格按知情同意和隐私规则。

推荐至少检验这些能力：

| 结果维度 | 可操作的验证 |
| --- | --- |
| 信息充分与覆盖 | 各个问题新增了哪些具体且非重复的事件、价值、行为与未知 |
| 推断校准 | 哪些模型判断得到本人核对和独立材料支持，哪些证据不足仍自信下结论 |
| 反例识别 | 有矛盾材料时能否主动保留，不得只拼一篇动人的人生叙事 |
| 预测/迁移（探索性） | 使用独立时间点/不同情境后续材料测试先前判断是否站得住 |
| 访谈成本 | 每个有用发现需要的轮次、用户主观负担、跳过率、主动终止率 |
| 人机体验 | 用户是否感到被准确理解而非讨好；是否容易直接纠正 AI |
| 隐私与安全 | 是否泄露其他人的资料、误升级外部方法、把普通情绪误判为临床状态 |
| 基线比较 | 固定问卷 vs 动态提问 vs 普通自由聊天；不同模型/提问者分别比较 |

问题库不是人格量表，不产生一个自称“真实自我百分比”的总分；即使后续评估很好，也不意味着穷尽了一个人。

## 9. 与仓库内已有模块的分工

- `prompts/guided-exploration.md`：给不知从何开始的用户提供交互规范；应按需调用 Discover Me，而不是直接复制整份题单给用户。
- `prompts/next-questions.md`：已有模型后挖掘未知；可以结合 Understand Me 的反证类问题。
- `prompts/full-report.md`：只有具备足够材料、用户明确要完整报告时才使用；不从六题凭空产出全量人格报告。
- `framework/human_ontology.md`：负责导航而非测量；Question Bank 不是新增人格维度。
- `framework/evidence_protocol.md`：每一题/答复都须接受来源和修正治理。
- 使用者的私人历史问句/生活材料可用于内部研究，但公开文件只接受**重新设计过的通用题与合成例子**，不能以改写方式泄露第三方与敏感细节。

**最终公式（方法论，而非数值模型）**：**好问题 = 用户愿意回答 + 对当前理解有新的区分度 + 能绑定具体生活事实 + 不超出隐私/负担边界 + 允许反驳和修正。**
